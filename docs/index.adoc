= CORS Library
:toc: right

== Introduction

NOTE: Versions 2.x target XP 8+.

A library for handling CORS (Cross-Origin Resource Sharing) headers in Enonic XP controllers and filters.

CORS lets browsers safely make cross-origin requests. This library reads your application's `.cfg` file and produces the correct `Access-Control-*` response headers, including full preflight (OPTIONS) handling with origin matching, method validation, and header validation.

The same `cors.origin` allowlist also drives an origin validator for WebSocket upgrades, which XP guards with a separate same-origin check of its own.

== Installation

Add the dependency to your `build.gradle` file:

[source,groovy]
----
dependencies {
    include "com.enonic.lib:lib-cors:${libVersion}"
}
----

== Usage

Import the library in a controller or filter:

[source,js]
----
var corsLib = require('/lib/enonic/cors');
----

=== Controller

Handle preflight requests with `respondOptions` and attach CORS headers to regular responses with `getHeaders`:

[source,js]
----
var corsLib = require('/lib/enonic/cors');

// Preflight (OPTIONS) — returns 204 with CORS headers, or 403 on rejection
exports.options = function (req) {
    return corsLib.respondOptions(req);
};

// Regular request — merge CORS headers into the response
exports.post = function (req) {
    return {
        contentType: 'application/json',
        headers: corsLib.getHeaders(req),
        body: JSON.stringify({ result: 'ok' }),
    };
};
----

Both `getHeaders` and `respondOptions` read configuration from `app.config` automatically.

=== Filter

Use the library as an XP filter to apply CORS headers across multiple controllers from a single place:

[source,js]
----
var corsLib = require('/lib/enonic/cors');

exports.filter = function (req, next) {
    if (req.method === 'OPTIONS') {
        return corsLib.respondOptions(req);
    }

    var response = next(req);
    var corsHeaders = corsLib.getHeaders(req);

    response.headers = response.headers || {};
    for (var key in corsHeaders) {
        if (corsHeaders.hasOwnProperty(key)) {
            response.headers[key] = corsHeaders[key];
        }
    }
    return response;
};
----

Register the filter in your `site.xml` (or equivalent descriptor) as described in the link:https://developer.enonic.com/docs/xp/stable/framework/filters[XP filter documentation].

=== WebSocket upgrade

XP performs its own same-origin check on a WebSocket handshake: a client served from a different
host than the app is rejected with `403` before the controller's response headers are ever read.
Returning a `checkOrigin` predicate on the `webSocket` object replaces that check with the
`cors.origin` allowlist:

[source,js]
----
var corsLib = require('/lib/enonic/cors');

exports.get = function (req) {
    return {
        webSocket: {
            data: {},
            checkOrigin: corsLib.getWebSocketOriginValidator(req),
        },
    };
};
----

WARNING: Supplying `checkOrigin` *replaces* XP's same-origin check rather than widening it. The
validator therefore accepts the app's own origin alongside the configured ones, so that same-origin
clients keep the access the platform was granting them for free.

XP calls the predicate during the handshake, after the controller has returned, passing only the
`Origin` header value. Everything it needs is captured when the controller builds it.

=== Explicit configuration

Pass a config map directly with `resolveHeaders` or `resolveOptionsResponse` instead of relying on `app.config`:

[source,js]
----
var corsLib = require('/lib/enonic/cors');

var config = {
    'cors.origin': 'https://example.com',
    'cors.credentials': 'true',
};

exports.options = function (req) {
    return corsLib.resolveOptionsResponse(config, req);
};

exports.post = function (req) {
    return {
        contentType: 'application/json',
        headers: corsLib.resolveHeaders(config, req),
        body: JSON.stringify({ result: 'ok' }),
    };
};
----

== Configuration

Add a configuration file for the consuming application (e.g. `com.example.myapp.cfg`) to the XP configuration folder:

[source,properties]
----
cors.origin = https://example.com, https://admin.example.com
cors.credentials = true
cors.allowedHeaders = Content-Type, Authorization
cors.methods = POST, GET
cors.exposedHeaders = X-Request-Id
cors.maxAge = 3600
----

[%header,cols="2,1,5"]
|===
| Key | Default | Description

| `cors.origin`
| _(not set)_
| Allowed origin(s). When omitted, CORS is disabled and no headers are added, and the WebSocket validator leaves XP's own same-origin check in place. See <<origin-matching>> below.

| `cors.credentials`
| `false`
| Set to `true` to send `Access-Control-Allow-Credentials: true`. Ignored (and not sent) when the resolved origin is `*`.

| `cors.allowedHeaders`
| _(not set)_
| Value for `Access-Control-Allow-Headers`. When omitted and the request includes `Access-Control-Request-Headers`, that value is reflected back. When configured, preflight requests for headers outside this list are rejected with `403`.

| `cors.methods`
| `GET, HEAD, POST`
| Value for `Access-Control-Allow-Methods`. Preflight requests for methods outside this list are rejected with `403`.

| `cors.exposedHeaders`
| _(not set)_
| Comma-separated list of extra response headers to expose to the browser via `Access-Control-Expose-Headers`. Duplicates are removed automatically.

| `cors.maxAge`
| _(not set)_
| Preflight cache duration in seconds (`Access-Control-Max-Age`).
|===

[#origin-matching]
=== Origin matching

The `cors.origin` property supports several formats:

`*`:: Responds with `Access-Control-Allow-Origin: *` for every request. Cannot be combined with `cors.credentials = true`.

Literal origin:: A plain `https://example.com` value. The incoming `Origin` header is compared against each entry in the comma-separated list. On a match, the request origin is reflected back and `Vary: Origin` is set. On no match, only `Vary: Origin` is returned.

`~`-prefixed regex:: A pattern starting with `~` is treated as a regular expression anchored to the full origin string. For example, `~https://.*\.example\.com` matches any subdomain of `example.com`. Multiple patterns can be mixed with literals in the same comma-separated list.

`~.*`:: Reflects any origin back verbatim. Unlike `*`, this variant is compatible with `cors.credentials = true`.

[source,properties]
----
# Literal origins
cors.origin = https://example.com, https://admin.example.com

# Regex: any subdomain of example.com
cors.origin = ~https://.*\.example\.com

# Mixed: literal and regex
cors.origin = https://example.com, ~https://.*\.dev\.example\.com

# Reflect any origin (supports credentials)
cors.origin = ~.*
----

== API

The library exposes seven functions:

=== `getHeaders(req)`

Returns CORS headers derived from `app.config` for use in regular (non-preflight) responses.

[.lead]
Parameters

[%header,cols="1,1,4"]
|===
| Name | Type | Description

| `req`
| object
| Incoming XP request object (must expose a `getHeader(name)` method).
|===

[.lead]
Returns

*object* — Key/value map of CORS headers to merge into the response `headers` field. Returns an empty object when CORS is disabled or the origin does not match.

[.lead]
Example

[source,js]
----
exports.get = function (req) {
    return {
        contentType: 'application/json',
        headers: corsLib.getHeaders(req),
        body: JSON.stringify({ result: 'ok' }),
    };
};
----

---

=== `respondOptions(req)`

Returns a complete preflight response derived from `app.config`.

[.lead]
Parameters

[%header,cols="1,1,4"]
|===
| Name | Type | Description

| `req`
| object
| Incoming XP request object (must expose a `getHeader(name)` method).
|===

[.lead]
Returns

*object* — `{ status: 204, headers: { ... } }` on success, or `{ status: 403, headers: {} }` when the preflight requests a disallowed method or header.

[.lead]
Example

[source,js]
----
exports.options = function (req) {
    return corsLib.respondOptions(req);
};
----

---

=== `resolveHeaders(config, req)`

Low-level variant of `getHeaders` that accepts an explicit config map instead of reading `app.config`.

[.lead]
Parameters

[%header,cols="1,1,4"]
|===
| Name | Type | Description

| `config`
| object
| Key/value map of configuration properties (same keys as the `.cfg` file).

| `req`
| object
| Incoming XP request object (must expose a `getHeader(name)` method).
|===

[.lead]
Returns

*object* — Key/value map of CORS headers.

[.lead]
Example

[source,js]
----
var config = { 'cors.origin': '~.*', 'cors.credentials': 'true' };

exports.get = function (req) {
    return {
        contentType: 'application/json',
        headers: corsLib.resolveHeaders(config, req),
        body: JSON.stringify({ result: 'ok' }),
    };
};
----

---

=== `resolveOptionsResponse(config, req)`

Low-level variant of `respondOptions` that accepts an explicit config map.

[.lead]
Parameters

[%header,cols="1,1,4"]
|===
| Name | Type | Description

| `config`
| object
| Key/value map of configuration properties.

| `req`
| object
| Incoming XP request object (must expose a `getHeader(name)` method).
|===

[.lead]
Returns

*object* — `{ status: 204, headers: { ... } }` on success, or `{ status: 403, headers: {} }` on rejection.

[.lead]
Example

[source,js]
----
var config = { 'cors.origin': 'https://example.com', 'cors.methods': 'GET, POST' };

exports.options = function (req) {
    return corsLib.resolveOptionsResponse(config, req);
};
----

---

=== `getWebSocketOriginValidator(req)`

Returns a `checkOrigin` predicate for a WebSocket upgrade response, derived from `app.config`.

[.lead]
Parameters

[%header,cols="1,1,4"]
|===
| Name | Type | Description

| `req`
| object
| Incoming XP request object (must expose `scheme`, `host` and `port`).
|===

[.lead]
Returns

*function | undefined* — A predicate taking the `Origin` header value and returning a boolean, or `undefined` when `cors.origin` is not configured. Returning `undefined` from the controller leaves XP's own same-origin check in place.

The predicate accepts an origin when any of the following holds:

* `cors.origin` is `*`.
* The origin equals the app's own origin, as built by <<get-request-origin,`getRequestOrigin`>>.
* The origin matches an entry of `cors.origin` (literal or `~`-prefixed regex).
* The `Origin` header is absent. Non-browser clients send none, and cross-site WebSocket hijacking requires a browser to send one. This is the opposite of the HTTP side, where a missing `Origin` simply means the request is not a CORS request.

The literal string `null` — the opaque origin sent by a sandboxed iframe or a `file://` page — is an ordinary string here, so it is rejected unless an allowlist entry matches it explicitly. An empty `Origin` is treated the same way: the header is present, so it is not the absent case, and XP's own check rejects it too.

[.lead]
Example

[source,js]
----
exports.get = function (req) {
    return {
        webSocket: {
            data: {},
            checkOrigin: corsLib.getWebSocketOriginValidator(req),
        },
    };
};
----

---

=== `resolveWebSocketOriginValidator(config, req)`

Low-level variant of `getWebSocketOriginValidator` that accepts an explicit config map.

[.lead]
Parameters

[%header,cols="1,1,4"]
|===
| Name | Type | Description

| `config`
| object
| Key/value map of configuration properties.

| `req`
| object
| Incoming XP request object (must expose `scheme`, `host` and `port`).
|===

[.lead]
Returns

*function | undefined* — The `checkOrigin` predicate, or `undefined` to keep XP's default check.

[.lead]
Example

[source,js]
----
var config = { 'cors.origin': 'https://console.example.com' };

exports.get = function (req) {
    return {
        webSocket: {
            data: {},
            checkOrigin: corsLib.resolveWebSocketOriginValidator(config, req),
        },
    };
};
----

---

[#get-request-origin]
=== `getRequestOrigin(req)`

Builds the origin a browser would send for a request to this app, normalized the way RFC 6454 and XP's own same-origin check normalize it: the port is omitted when it is the scheme's default.

[.lead]
Parameters

[%header,cols="1,1,4"]
|===
| Name | Type | Description

| `req`
| object
| Incoming XP request object (must expose `scheme`, `host` and `port`).
|===

[.lead]
Returns

*string | undefined* — The app's own origin, or `undefined` when `scheme` or `host` is missing.

[.lead]
Example

[source,js]
----
// scheme 'https', host 'api.example.com', port 443
corsLib.getRequestOrigin(req); // 'https://api.example.com'

// scheme 'http', host 'localhost', port 8080
corsLib.getRequestOrigin(req); // 'http://localhost:8080'
----
